## 3. ANSWER TWO — the smallest trailer that would carry it

Two candidates, measured against the rule *the generator owns it and the
gate enforces it*, which needs the source to be **on disk and
deterministic offline** (CI's docs lane runs with no GitHub token; the
snapshot check already needs `fetch-depth: 0` for the same reason, D78).

**(a) Derive from git.** `git log --first-parent` subjects: 47 of 76,
never 76, and a subject is free prose. **Refused as the source**; kept as
a cross-check.

**(b) The record carries one line per landing.** A merge-recording
report — the thing that is written at every landing already, 32 times
so far — gains one fixed-format line directly under its title:

```
**Landed:** PR #77 · 53d676d · 2026-10-10 · AMBER · checked: the wall-properties dialog (his word); the other two on their tests
```

Five fields, `·`-separated; the last free. The generator reads every
`docs/handoff/*.md` for a `**Landed:**` line, every `defects/*.md`'s
front matter for `closed_by`, and `ROADMAP.md` §3 for the RED list, and
writes `STATUS.md`. **The one-time backfill** writes that line into the
32 existing merge reports from the census above and the GitHub merge
dates (which I hold), and a `docs/handoff/0000-landings.md`-style stub —
or the plan's frozen table — carries the pre-mailbox PRs #1–#29 so the
nine named nowhere stop being invisible. After that the board is derived
from the record and nothing else.

**What the gate checks, so the line cannot be forgotten:**
`status_index.py --check` fails if `STATUS.md` differs from a
regeneration (the `defects_index` shape, never stale since); and — the
enforcement where it matters — **a first-parent commit on `main` whose
subject says `PR #N` with no `**Landed:** PR #N` anywhere in `handoff/`
is RED.** The landing commit and the report that records it are written
minutes apart by the same hand; the check closes that gap exactly where
0217 §3 and 0219 §2 say I have left things ahead of or behind the record
before.
